# 프로젝트 용어집

## 목적

이 문서는 Beans on Time의 설계 문서, 코드, 테스트와 작업 보고에서 사용하는 공통 용어의
기준 문서다.

공통 용어의 의미와 표현은 이 문서를 기준으로 한다. 구체적인 상태값, 불변식, 상태 전이와
정책은 해당 개념을 소유하는 애그리거트 문서에서 관리한다.

Java 식별자, API 경로, 프레임워크와 기술 고유명사는 원래 표기를 유지한다. 같은 개념을
설명할 때 영어와 한국어 표현을 불필요하게 혼용하지 않는다.

---

# 공통 설계 용어

## 애그리거트

하나의 비즈니스 일관성 경계 안에서 함께 변경되는 도메인 객체의 집합이다.

애그리거트는 자신의 불변식을 보호하고 상태 전이를 소유한다. 다른 애그리거트는 객체
그래프로 포함하지 않고 식별자로 참조하는 것을 기본으로 한다.

## 애그리거트 루트

애그리거트 외부에서 애그리거트의 상태와 행위에 접근하는 진입점이다.

애그리거트 루트는 애그리거트 전체의 불변식을 보호하며, 상태 변경은 의미 있는 도메인
행위를 통해 수행한다.

## 불변식

애그리거트가 생성되거나 상태가 변경된 뒤에도 항상 만족해야 하는 비즈니스 규칙이다.

구체적인 불변식과 위반 예외는 해당 애그리거트 문서와 도메인 모델에서 정의한다.

## 생명주기 상태

도메인 개체가 비즈니스 생명주기에서 어느 단계에 있는지를 나타내는 상태 축이다.

각 애그리거트가 사용할 수 있는 상태값과 상태 전이를 소유한다. 일시적인 외부 조건이나
실행 실패 원인을 생명주기 상태에 임의로 합치지 않는다.

## 실행 차단 사유

생명주기 상태와 독립적으로 특정 실행을 막는 시스템 또는 외부 조건의 원인이다.

현재 이 용어의 구체적인 모델과 규칙은 구독 애그리거트가 소유한다. 실행 차단 사유를
별도의 애그리거트 공통 타입으로 해석하거나 다른 도메인에 선제적으로 일반화하지 않는다.

## 도메인 행위

도메인 객체가 자신의 상태와 불변식을 보호하면서 수행하는 의미 있는 비즈니스 동작이다.

`setStatus` 같은 일반 상태 변경보다 `pause`, `resume`, `cancel`처럼 비즈니스 의도를
드러내는 표현을 사용한다.

## 애플리케이션 서비스

유즈케이스를 조율하는 애플리케이션 계층의 구성 요소다.

애그리거트 로드, 도메인 행위 호출, 저장과 여러 포트의 조율을 담당할 수 있지만,
도메인 객체가 소유해야 하는 규칙을 대신 구현하지 않는다.

## 조회 모델

특정 조회 유즈케이스에 필요한 데이터를 표현하는 읽기 전용 모델이다.

애그리거트 구조를 그대로 복제할 필요가 없으며 여러 도메인의 조회 정보를 조합할 수
있다. 조회 모델의 조합은 애그리거트 경계를 변경하지 않는다.

## 소유권 인가

인증된 주체가 변경하거나 조회하려는 도메인 대상의 소유자인지 확인하는 인가다.

역할 기반 인가와 구분하며, 구체적인 인증·인가 경계는 `docs/adr/security.md`를 따른다.

# 공통 비즈니스 용어

## 구독 회차

한 번의 결제로 확보한 선결제 이용 기간을 뜻한다. 현재 코드의 `currentPeriod`는 전체
이용 이력이 아니라 ACTIVE 상태에서 현재 실제로 사용할 수 있는 구간만
`SubscriptionPeriod`로 표현한다. PAUSED에서는 남은 이용권을 `remainingPaidDays`로
표현한다.

구독 회차는 청구 일정이나 납품 주기와 같은 시간 개념이 아니다. 구체적인 기간 확정
규칙은 `docs/subscription.md`를 따른다.

## 청구 일정

정기 결제가 예정된 업무 날짜와 그 계산 기준을 뜻한다. 현재 구독에서는
`BillingAnchorDay`와 `nextBillingDate`로 표현한다.

청구 일정이 도래했다는 사실만으로 결제 실행이 가능하다는 뜻은 아니다.

## 납품 주기

구독 상품을 반복해서 배송하는 간격이다. 현재 코드에서는 `DeliveryCycle`로 표현한다.

납품 주기는 결제 회차나 청구 일정이 아니며, 구체적인 배송 일정 계산 정책은 아직
확정되지 않았다.

---

# 용어 관리 원칙

- 여러 애그리거트와 문서에서 같은 의미로 사용하는 용어만 공통 용어로 관리한다.
- 특정 애그리거트의 상태값, 불변식, 상태 전이와 정책은 해당 애그리거트 문서에 둔다.
- 공통 용어라는 이유만으로 공통 코드 타입이나 범용 추상화를 만들지 않는다.
- 용어의 의미나 소유 범위가 변경되면 이 문서와 관련 애그리거트 문서를 함께 갱신한다.
- 아직 확정되지 않은 정책은 용어 정의를 근거로 선제적으로 구현하지 않는다.
