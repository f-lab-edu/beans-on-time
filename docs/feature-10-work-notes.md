# feature/10 작업 재개 메모

## 보존 목적

2026-09-19 기준, 작업 중인 변경을 먼저 커밋하고 최신 원격 main을 feature/10에
머지하기 전에 남긴 메모다. 이번 범위는 작업 보존과 브랜치 통합이며 기능 완성이나
기존 문제 수정은 포함하지 않는다. 머지 전 HEAD는 `83de338`이다.

## 현재까지의 작업

- 상품 등록 응답과 공개 단건 조회를 위한 응답 DTO, 입력·출력 조회 포트, 서비스,
  InMemory 조회 어댑터와 상품 부재 404 처리를 추가했다.
- 상품 API 테스트에 판매자 신원 적용, 공개 조회, 가격 검증, 역할 인가와 ID 검증을 담았다.
- `SellerId`를 seller 도메인 패키지로 분리했다.
- `Product`, `DeliveryCycle`을 record로 바꾸고 상품·구독·청구의 접근자 호출을 수정했다.
- `ProductId`의 생성자 검증을 Jakarta Validation 어노테이션으로 변경했다.
- 납품 주기 입력을 `DeliveryCycleUnit.of()`에서 `1주`, `1달`로 해석하도록 변경했다.
- 구독 요청 검증 어노테이션을 수정하고 일시정지 종료일에 최대 3개월 제한을 추가했다.
- README의 구현 현황과 아키텍처·보안·코딩·테스트·리뷰 및 에이전트 작업 지침을 정리했다.

## 머지 후 이어서 확인할 항목

아래 항목은 확정된 새 정책이나 완료된 검증이 아니라 후속 점검 목록이다.

- [ ] 상품 조회 관련 신규 파일과 seller 식별자 파일이 통합 결과에 모두 포함되는지 확인한다.
- [ ] record 전환에 따른 호출부·테스트 컴파일과 상품 컬렉션의 불변성 보장을 확인한다.
- [ ] `ProductId`의 생성자 검증 제거로 직접 생성 시 잘못된 ID를 허용하는 경로를 검토한다.
      Jakarta Validation 의존성과 순수 Java 도메인 경계도 함께 확인한다.
- [ ] 구독 Controller의 요청 파라미터와 중첩 `deliveryCycle`의 `@Valid` 적용을 확인한다.
      누락·null·0 이하 간격 입력과 잘못된 단위가 의도한 HTTP 오류로 처리되는지 검증한다.
- [ ] `1주`, `1달` 입력 계약을 HTTP 요청 예시·기존 테스트·응답의 enum 표기와 대조한다.
- [ ] 일시정지 3개월 제한의 정책 확정 여부와 경계값을 확인한다. 현재 구현의
      `LocalDate.now()` 직접 호출은 애플리케이션의 KST Clock 전달 규칙과 충돌한다.
      정책을 확정한 뒤 기준 날짜, 도메인 문서와 테스트를 함께 맞춘다.
- [ ] `./gradlew spotlessCheck test`로 최종 통합 상태를 검증한다.

## 기존 검증 상태

메모 작성 전에는 현재 변경에 대한 새 테스트를 실행하지 않았다. 로컬에 남아 있는
2026-09-05 테스트 XML에는 Docker 환경을 찾지 못해
`BeansOnTimeApplicationTests`가 실패한 기록이 있다. 과거 결과를 현재 변경의 통과 근거로
사용하지 않는다.

## 작업 재개 기준

머지 커밋의 첫 번째 부모는 보존한 feature/10 작업이고 두 번째 부모는 반영한 main이다.
두 부모와 머지 결과를 비교하면 기존 작업과 main에서 들어온 변경을 구분할 수 있다.
후속 수정은 이 메모와 최신 도메인·아키텍처 문서를 대조한 뒤 작은 범위로 진행한다.
